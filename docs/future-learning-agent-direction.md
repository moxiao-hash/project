## 1. 用户希望实现的产品

StudyPilot 长期希望发展为可适配不同课程的学习 Agent，不局限于开发者自己的 Java + AI 学习路线。

用户可以提供资料，也可以只表达学习目标。AI 应帮助理解目标、组织资料、制定学习计划，并在后续学习中根据进度与学习结果持续辅助和调整。产品需要实现实际业务操作和状态保存，而不只是通过聊天输出一份计划。

当前 Java + AI 路线未来可以作为一个内置模板保留。现有开发成果不因这一长期方向而立即推倒重做。

## 2. 两种核心入口

### 2.1 用户自行导入资料

用户上传课件、教材、笔记或提供资料链接，说明想学什么、现有基础、截止日期及可用时间。

预期流程：

1. AI 解析资料，识别章节、知识点和资料覆盖范围。
2. 对解析失败、内容不完整或关键信息缺失明确提示，必要时向用户追问。
3. 根据用户目标和时间约束提出课程结构、学习计划及资料来源。
4. 用户确认后，将计划保存为可执行、可追踪的学习任务。
5. 在学习过程中提供讲解、练习和反馈，并依据真实学习结果提出调整。

示例：用户上传《软件工程》课件，要求在两周内每天学习一小时，AI 制定计划并从第一章开始辅导。

### 2.2 用户描述目标，由 AI 联网寻找资料

用户没有准备资料，只说明想学习的课程或技能。

预期流程：

1. 澄清学习目标、基础、可用时间和预期成果。
2. 联网检索并筛选相关资料，说明选择依据与来源。
3. 识别资料缺口、相互冲突和可访问性问题，不能把找到链接等同于已读取完整内容。
4. 基于可用资料生成课程结构和计划，交由用户确认。
5. 进入与资料导入模式相同的学习流程。

两种入口应共用后续计划、任务、学习进度和反馈机制，不发展成两套互不相通的产品。

## 3. 希望形成的学习闭环

```text
学习目标 + 用户资料 / 联网资料
                  ↓
          澄清目标与解析资料
                  ↓
          课程结构与计划草案
                  ↓
              用户确认
                  ↓
         今日学习、讲解与练习
                  ↓
         学习证据与掌握情况记录
                  ↓
         调整后续任务并继续学习
```

Agent 应读取真实业务状态，通过受控工具执行操作，并保留过程与结果。模型失败、搜索不可用、执行未完成时应如实反馈；刷新页面或重新进入会话后应能够继续。

后续可使用“今天没学完，而且刚才两题答错了，请调整明天的内容”检验系统是否真正串联学习、反馈和计划调整。

## 4. 后续通用化的候选设计

以下为本次讨论提出的建议，不是已经批准实施的详细架构。

| 层次 | 候选职责 |
| --- | --- |
| 通用学习核心 | 目标、资料、课程结构、计划、任务、进度、会话与审计 |
| 学习空间 | 隔离同一用户的不同课程及其资料、检索上下文、计划和掌握度 |
| 领域能力 | 按课程启用不同学习和验收方式，例如编程测试、概念测验、简答反馈 |
| 内置模板 | 保留 Java + AI 等预置路线，作为通用系统的具体使用场景 |

现有身份隔离、资料处理、检索、计划任务、工具治理、会话恢复和自动化可以作为复用基础。后续重点评估：

- 将固定 Java + AI 的学习范围和搜索偏好改为课程级配置。
- 将固定路线导入与用户自定义课程结构区分开。
- 明确资料、会话、计划及掌握度的学习空间归属，避免跨课程串用。
- 将代码运行、补丁、Git 等能力保留为编程方向的可选增强，不作为所有课程的必经步骤。
- 不把所有课程都套用同一评分方式；AI 反馈与确定性验证需要区分。

## 6. 支付接入的目的与时机

用户主要目的是丰富项目、亲自经历完整支付接入过程，近期真实付费量可能较少，但不排除以后正式上线。

最终希望完成的验收是：

```text
用户点击订阅 → 进入扫码付款界面 → 使用正式支付宝支付小额真实资金
→ 后端通过官方通知或查单确认支付 → 自动开通套餐 → 页面刷新权益
```

用户更希望使用真实资金，即使金额很小。沙箱用于前期开发与验证，不替代最终真实交易验收。具体交易金额、套餐和付款安排尚未确定。

本次讨论的建议是：支付放在核心学习闭环稳定之后，不要求等待所有长期功能全部完成。当前先保留方案，不启动完整支付开发。

启动前可检查：

1. 用户已经能完成一个学习单元，Agent 能保存状态、恢复会话并调整任务。
2. 明确首个付费权益及其实际效果。
3. 平台承担的模型调用能够计量并限制成本。
4. 具备正式收款权限及可达的通知地址。
5. 能处理重复通知、漏通知、开通失败与退款后的权益变化。

## 7. 支付调研结论与限制

调研入口为支付宝官方“AI 网页应用收款”。2026-09-07 在用户登录后的申请页面观察到：

- 表单支持选择“网站未上线”，该分支要求首页、商品或服务页、支付页截图。

## 8. 订阅方案暂不定稿

此前讨论过“基础版 + Pro 30 天”、较高 AI 额度、深度成果评审和自动化等候选权益。这些建议基于当前 Java + AI 产品，不应直接固化为通用学习平台的最终套餐。

未来可以围绕学习空间数量、资料容量、个性化辅导和高级自动化重新评估。价格、免费额度、会员额度和自动续费均未确定。

保留的设计原则：

- 基础用户能完成有价值的学习流程。
- 会员到期保留已有学习历史、资料与成果。
- 用户自带 AI Key 与平台承担的模型费用分开考虑。
- Pro 不等于无限模型调用，也不改变 Agent 原有的权限和确认边界。
- 付费权益必须由后端验证，不能只靠前端隐藏按钮。

旧文档 [订阅制与自动化收款 PRD](subscription-payment-automation-prd.md)保留为历史方案参考，其多渠道、挂机监听、套餐价格和实施顺序均不代表当前已决定采用。

**合并原则：第 1～9 节的产品思想、两种学习入口和开发先后顺序保持不变。** 本次仅补充候选工程实践及实际上线的准备事项，不启动支付开发、主体注册、购买服务器或备案申请，不将产品改成固定 Java + AI 课程商店。

### 10.1 吸收的工程建议

- Java 统一管理订单、付款事实、订阅有效期和额度；Python 使用受控业务服务，不能自行发放会员。
- 金额以整数分保存，对接支付宝时使用精确十进制；下单价格由服务端套餐配置确定。
- 支付渠道与权益发放解耦，保留沙箱和正式环境切换能力。Mock 只作为隔离测试替身，不算用户要求的真实支付验收，也不能在正式环境提供任意开通入口。
- 验签之外核对应用、收款方、订单、金额和交易状态；回调与主动查单共用幂等处理。单笔付款只能发放一次权益，不同续费订单并发时也要保护用户到期时间。
- 支付成功与权益发放成功分别记录，支持失败重试与补偿；不能在订单变为 PAID 后永久跳过未完成的权益发放。
- 开发时可评估临时 HTTPS 隧道承接通知，仅映射必要接口，不公开数据库、内部服务和管理入口；公网可达不代表满足正式商户审核。
- 后续提供会员状态、使用额度和订单记录页面；具体套餐、额度与展示形式仍待评审。

### 10.2 不直接照搬的内容

| 合作者方案内容 | 本项目处理方式 |
| --- | --- |
| Pro 无限计划、无限测验和无限 AI 调整 | 不采用无限承诺；结合模型成本、平台 Key/自带 Key 和并发限制再制定额度 |
| 订阅拦截仅从 SecurityContext 获取身份，Pro 直接放行 | 后台任务和内部工具也需显式绑定用户及学习空间；业务服务统一校验，Pro 仍受资源限制；AOP 仅为可选封装 |

| 每天定时清零用量 | 可按用户、额度类型和明确时区下的日期分桶，原子预占、结算与释放；不依赖清零任务成功才恢复额度 |

## 11. ICP 备案、主体与正式上线的准备事项

本节是上线前的判断框架，不是认定本项目已具备上线资质。最终应按实际运营主体、所在省份、部署方式、业务内容及届时规则核实。

### 11.1 区分四件事

| 事项 | 解决的问题 | 对 StudyPilot 的含义 |
| --- | --- | --- |
| ICP 备案 | 非经营性互联网信息服务的备案管理 | 使用中国内地服务器对外提供网站服务时，应按接入商和主管部门要求办理；不能因为网站免费或只做演示就直接认定免备案 |
| ICP 等增值电信业务经营许可 | 实际业务是否属于需要许可的电信业务 | 不等于普通备案；需按实际服务模式判断，不能只看是否有支付按钮 |
| 支付产品签约 | 账户、经营类目、网站材料是否满足支付机构要求 | 商户开通与网站备案相互独立；开通支付不代表网站经营手续已完成 |
| 公安联网备案及其他适用要求 | 网站安全管理等独立义务 | ICP 备案不能替代；上线前按所在地公安机关和官方平台要求核实适用范围、期限及材料 |

法规区分经营性互联网信息服务许可与非经营性备案。对于具体业务，四川省通信管理局的解答还区分了自营商品/服务销售与其他增值电信业务，因此不能把“有收费功能”机械等同于“一定需要 ICP 许可证”，也不能认定“自营 AI 服务必然不需要”。StudyPilot 涉及 AI 辅导、信息生成和可能的内容服务，上线前应提交真实业务说明向所在地通信管理局核实分类。

依据：[工信部《互联网信息服务管理办法》](https://www.miit.gov.cn/zwgk/zcwj/flfg/art/2020/art_4c6a91eb93c34a6e8adc5852f9b56fd1.html)、[非经营性备案管理办法](https://www.miit.gov.cn/gyhxxhb/jgsj/cyzcyfgs/bmgz/xxtxl/art/2024/art_84a0cfa0ebd049bbbe751dca9a008e56.html)、[四川省通信管理局许可解答](https://scca.miit.gov.cn/bsfw/gsgg/art/2024/art_96d65dca5934436ea2c7c1e58679ab26.html)。

### 11.2 部署地区与备案的关系

- **中国内地部署**：先确认域名实名主体、备案主体和云资源的备案资格，通过实际接入商办理相应手续。备案通过后按要求展示备案号、链接，并保持实际服务与备案信息一致；更换接入商或主体时评估接入备案、变更或重新备案。
- **中国香港或海外部署**：按云服务商接入规则，这些节点通常无需办理中国内地 ICP 接入备案。但这不自动免除其他适用义务，也不保证支付宝接受未备案的经营网站。
- **域名、前端、后端和回调地址分别梳理**：不能仅凭服务器品牌判断地域；实际节点、内地 CDN 或代理接入也可能影响要求。不能用一个已备案空壳网站掩盖真实经营网站或不一致的主体。

依据：[阿里云服务器地域与备案说明](https://help.aliyun.com/zh/icp-filing/basic-icp-service/user-guide/icp-filing-server-access-information-check)、[备案办理流程](https://help.aliyun.com/zh/icp-filing/basic-icp-service/user-guide/icp-filing-application-overview)。

### 11.3 对合作者备案结论的修正

1. **不采纳“支付宝、微信所有直连接口都强制要求回调域名 ICP 备案”的统括结论。** 当前核实到的支付宝申请页面，是已上线经营网站链接的备案要求；通知接口文档描述的是地址和通知处理要求。两者不能混用。具体支付产品如另有回调域名、主体或白名单限制，需要分别核实，不能据此反向保证回调域名一定无备案要求。
2. **不采纳“用第三方收款平台就无需给自己的网站备案”。** 平台代收改变支付链路，不改变 StudyPilot 自身的部署和网站管理要求。
3. **不采纳“办个体户即可解决全部商业化资质”。** 个体工商户可能有助于申请商户支付，但若实际业务需要增值电信业务经营许可，其主体条件还需单独核实；相关许可指南列明经营者为依法设立的公司，不能将个体执照等同于已满足许可条件。[江苏省通信管理局许可指南](https://jsca.miit.gov.cn/gzcy/gggs/art/2025/art_1d7aec0258754cfe90acf6f350c34894.html)
4. **保留个人官方收款入口的实测结果。** 合作者“个人无法直接开通官方网页支付”的绝对表述，不能覆盖本次已观察到的 AI 网页应用收款个人申请路径；能进入表单仍不等于最终获批。
5. **不将办理成本、秒批、免税额度或最低费率作为承诺。** 是否注册主体、以个人还是单位备案，应根据真实经营方式决定；不得用不符合实际用途的个人备案包装商业网站。

### 11.4 未来真正准备上线时的顺序

1. **描述真实业务**：确认目标用户、是否公开注册、免费或收费、AI 生成内容范围、用户上传资料是否仅私人使用。沿用通用学习 Agent 目标，不为通过审核而虚构经营类目。
2. **确认主体与业务分类**：向所在地通信管理局、拟用接入商和支付机构分别核实网站备案、经营许可、商户材料；再决定是否需要设立主体，避免先购买代办服务。
3. **确定部署与域名**：列出前端、API、支付通知、存储和 CDN 的地域与域名，准备相符的实名和备案资料；明确域名、服务器及支付账号的持有人和协作者权限。
4. **完成适用的网站手续**：按实际要求办理备案、许可及公安联网备案；不把未上线截图申请作为永久替代网站手续的方式。
5. **申请支付并准备服务说明**：提交真实的首页、服务与付款页面，核实限额、费率、有效期、退款和续期资料要求；开通结果以平台审核为准。
6. **发布与验收**：配置 HTTPS、备份恢复、身份隔离和最小公网入口；完成官方验签、查单、权益发放和退款联调后，再执行约定的小额真实交易。

这些工作只在后续确定上线范围后执行，不改变“先完成当前 Agent 开发，再评审通用化与支付”的安排。

### 11.5 与学习 Agent 直接相关的上线核实项

- 对外开放用户资料上传前，明确资料存储、删除、模型处理及第三方传输说明；上传用于私人学习不等于获得公开传播教材的授权。
- 面向境内公众提供生成式 AI 服务时，应重新核实生成式 AI、内容标识以及适用的登记/备案要求；不能因为底层模型已经备案就认定应用无需任何手续。开发自用与公开服务的适用范围有区别。[国家网信办《生成式人工智能服务管理暂行办法》](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm)
- 是否涉及教育培训等额外准入，应结合实际提供的服务核实；“学习工具”名称本身不能代替业务判断。
