# StudyPilot 架构基线

> 状态：v0.1，项目初始化阶段。

## 1. 单仓库边界

```text
┌───────────────┐
│ web           │  Vue 3 学习工作台、计划表单、对话与执行记录
└───────┬───────┘
        │ HTTPS / SSE
┌───────▼───────┐
│ backend       │  Spring Boot：身份、授权、业务事实、审计
└───────┬───────┘
        │ 内部 HTTP，短期服务令牌
┌───────▼───────┐
│ ai-service    │  FastAPI：RAG、模型路由、Agent、工具编排
└───────┬───────┘
        │
  云端模型 API / 本地 Ollama
```

## 2. 服务职责

### `backend/`

后续采用按业务领域组织的模块化单体，而不是一开始拆微服务：

```text
user/       账户、用户设置和数据隔离
learning/   学习目标、计划、任务、进度与版本
material/   资料元数据、处理状态与来源策略
assessment/ 知识点、题目、作答与掌握度
agent/      授权记录、执行任务、操作审计和 Java 工具 API
shared/     异常、认证、时间、分页等跨领域能力
```

Spring Boot 负责所有写业务数据的决策。任何 Agent 请求都必须经过用户身份、授权范围、参数校验和审计。

### `ai-service/`

FastAPI 负责变化较快的 AI 编排：资料解析、检索、模型路由、计划草案、测验生成和工具调用循环。它通过受控 Java API 读取或请求业务操作，绝不直连 MySQL 写入核心数据。

### `web/`

Vue 负责响应式交互。桌面端优先资料与计划管理，移动端优先今日任务、打卡和快速对话。它显示简洁的 Agent 执行状态，不展示模型内部推理。

### `infra/`

保存 Docker Compose、环境变量样例、健康检查与部署说明。基础设施只在相关能力实际需要时引入，避免初始化阶段出现未使用的服务。

## 3. 关键架构约束

1. **API 优先**：Agent 首选调用 Java 的结构化工具 API；GUI 自动化仅预留适配器，作为后续受控兜底。
2. **确认后写入**：首次计划由对话生成草案，用户通过结构化表单确认后才写入业务库。
3. **可审计执行**：自动调整计划、生成内容和失败结果均需持久化执行记录。
4. **可撤销变更**：计划调整保存版本与差异，高风险变更需确认。
5. **隐私路由**：资料隐私级别决定云端 API、本地 Ollama 或脱敏处理路径。
6. **幂等任务**：同一计划、日期和触发原因不能重复成功调整，防止打卡触发与夜间检查重复执行。

## 4. 演进顺序

```text
学习目标 → 计划与任务 → 资料管理 → AI 对话
→ RAG 与来源 → 测验与掌握度 → Agent 自动调整
→ Redis/异步任务/向量库 → Docker 部署 → GUI 兜底（可选）
```

前几个迭代只使用 Java、MySQL 和前端的必要部分。Python AI 服务不是起点，而是在稳定业务模型基础上接入。
