# StudyPilot（暂定名）产品需求与 MVP 范围说明

> 版本：v0.1
> 日期：2026-07-24
> 状态：需求已确认，待进入架构设计

## 1. 产品愿景

StudyPilot 是一款面向个人学习者的 AI 学习执行工作台。它将用户的学习资料、学习目标、可用时间和学习表现汇聚到一个系统中，并在用户授权的范围内完成资料整理、计划调整、测验生成等低风险操作。

产品的目标不是提供一个泛聊天机器人，而是形成一个可追踪、可调整、可审计的学习闭环：

```text
导入资料 → 理解内容 → 生成并确认计划 → 执行每日任务
→ 完成测验/记录表现 → Agent 调整后续计划 → 进入下一轮学习
```

首个内置使用场景为“在年底前完成 Java + AI 智能应用项目”的学习路径。开发者本人将作为首位真实用户，用该产品管理自己的项目学习过程。

## 2. 目标用户与边界

### 2.1 目标用户

- 当前：单个个人学习者，优先服务开发者本人。
- 架构：按多用户数据隔离设计，具备账户、登录、个人设置与独立数据空间。
- 非目标：不开发学习小组、共享资料、排行榜、教师端或管理员协作功能。

### 2.2 语言和内容

- 界面与 Agent 对话：中文优先。
- 学习内容：支持中文资料，同时优化英文技术文档、代码与 Java/Python/AI 学习场景。

## 3. 核心体验

### 3.1 双入口工作台

- **任务工作台**：默认首页，展示今日任务、阶段进度、待复习内容、资料状态、站内通知和近期计划变更。
- **Agent 对话入口**：固定可见。用户可用自然语言建立目标、提问、请求调整计划或查看执行结果。
- 两个入口操作同一套学习计划、任务和资料数据；对话不能绕过业务规则直接修改数据。

### 3.2 对话式初始化

用户通过对话描述目标，例如“我想在年底前完成 Java + AI 项目，每周约学习 10 小时”。Agent 追问必要信息：

- 截止日期；
- 当前基础；
- 每周可用时间；
- 学习偏好与强度限制；
- 是否使用内置 Java + AI 学习路线模板。

Agent 最终以结构化表单呈现计划草案，用户可微调并确认。只有确认后的计划才会正式落库并生成初始任务。

### 3.3 Agent 执行透明度

对话采用流式输出，并展示简洁状态，例如“正在检索资料”“已生成 5 道测验题”“已将 2 个任务顺延至周末”。

系统不展示模型原始内部推理。所有实际业务操作在计划/任务页面保留可展开的执行记录，包括：触发原因、工具调用、影响对象、执行结果、失败原因和撤销入口。

## 4. MVP 功能需求

### 4.1 账户与个人设置

- 注册、登录、退出与会话管理。
- 用户数据隔离。
- 设置学习时区、每周可用时间模板、每日学习时长上限、周末偏好和默认隐私策略。
- 保留模型调用策略和授权范围的个人配置入口。

### 4.2 学习资料与知识库

支持导入：

- Markdown / TXT 笔记；
- PDF 课程资料；
- 网页链接或复制的文章内容；
- 图片和扫描件。

资料处理规则：

- PDF、网页和图片解析均采用异步任务，上传请求不得长期阻塞。
- 图片和扫描件 MVP 只保证印刷体 OCR；手写笔记、复杂表格和公式识别属于后续增强项。
- 用户可将资料标记为：`学习路线/课程大纲`、`学习材料`、`个人笔记`、`参考资料`。
- 系统保存原始文件/链接、解析文本、提取摘要、主题、知识点、标签和处理状态。

### 4.3 知识检索与联网搜索

资料库与联网搜索同等参与回答和计划生成；但来源优先级按任务类型处理：

```text
用户当前指令与硬约束
  > 用户标记的学习路线/课程大纲（决定学习路径）
  > 用户普通资料 与 联网检索资料（共同参与检索）
  > Agent 的常识性补充
```

- 技术事实、框架 API 和版本差异优先采用最新官方资料。
- 学习路径、章节顺序和指定教材以用户提供的大纲为准。
- 来源冲突无法可靠裁决时，Agent 必须说明冲突及依据，而不是输出伪确定结论。
- 联网结果默认保存 URL、标题、引用片段、检索时间和来源类型；用户确认后，网页内容才进入个人长期知识库。
- 回答与计划建议应呈现可追溯来源标识。

### 4.4 学习目标、计划与任务

- 创建、查看、修改学习目标与截止日期。
- 提供“Java + AI 智能应用开发”内置学习路线模板，允许用户微调。
- 根据用户资料、目标、可用时间和基础生成分阶段学习计划与每日任务。
- 计划确认后生成任务；任务支持完成、跳过、延期、查看关联资料和知识点。
- 计划与任务均需版本化，记录变更前后差异。

### 4.5 自适应学习与测验

- Agent 自动提取资料主题、摘要、知识点和标签。
- 每个学习单元可生成选择题与解析；题目应关联来源资料和知识点。
- 保存题目、参考答案、用户作答、得分、关联知识点、题目生成时间与模型版本。
- 掌握度以小测表现为主，任务完成情况为辅，用户自评作为校正信号。
- Agent 可以根据低掌握度插入复习任务、降低推进速度或推荐补充材料。
- 题型演进：MVP 为单选/多选；后续加入简答；最后才引入编程题与隔离代码判题。
- 编程题的难度与比例应随掌握度提升：补全/找错 → 方法实现 → 综合小模块。

### 4.6 Agent 授权与自动执行

V1 的自动化范围仅限低风险操作：

- 解析资料并提取知识点；
- 生成测验与复习内容；
- 在已确认计划约束内，小范围重排未完成任务。

高风险操作必须展示预览并要求确认：

- 删除资料或任务；
- 修改长期目标、截止日期或学习约束；
- 大范围重排计划；
- 未来涉及外部系统写操作。

执行规则：

- 用户打卡后即时检查并在必要时调整计划。
- 每日晚间定时检查未打卡/逾期情况，并作为兜底触发器。
- 同一计划、日期和触发原因的调整必须幂等，避免重复重排。
- 每次变更可查看历史，并支持恢复到上一版计划。

### 4.7 日历与通知

- V1：用户手动设置每周可用时间模板；Agent 只在系统内部安排任务。
- 后续日历路线：只读忙闲时间 → 用户确认后同步选定任务 → 授权后自动同步。
- 日历读取应只传递标准化可用时间段给 Agent，不传递会议标题、参与人和备注等隐私内容。
- V1 仅提供站内通知和首页摘要；不接邮件、Web Push、微信、钉钉等外部消息渠道。

## 5. 数据隐私与模型策略

采用混合模型模式：

- 云端模型 API 为默认主力，处理计划生成、联网问答、测验生成和复杂工具调用。
- 本地 Ollama 作为开发调试、敏感资料处理和云端不可用时的备选。
- 每份资料可标记为普通、敏感、仅本地；模型路由必须遵守该策略。
- 记录每次模型调用的模型、Token、延迟、成本估算、资料隐私策略和执行结果。
- 设置单次任务、每日调用及循环次数上限，防止 Agent 产生意外成本或无限执行。
- 云端不可用时需明确显示降级状态，不得伪造成功结果。

## 6. 外部操作与 GUI 兜底

系统优先通过受控业务 API 执行操作。GUI/键鼠自动化只作为后续集成没有 API 的旧系统时的严格受控兜底能力：

```text
Java 业务 API 优先 → GUI 自动化适配器（受控）→ 停止并提示人工处理
```

当前仅预留 `GuiAutomationTool` 抽象接口和操作预览能力，不将实际 GUI 自动化列为年底 MVP 的必交付项。若核心功能提前完成，可使用本地模拟旧系统与 Playwright 演示固定表单自动化。

GUI 兜底必须具备目标白名单、用户确认、截图与动作审计、界面异常即停止、禁止向模型暴露账号密码/验证码/敏感 Token 等约束。

## 7. 技术边界（已确认）

```text
Vue 3 + TypeScript + Vite
        ↓
Spring Boot（模块化单体）
账户、授权、计划、任务、测验、审计、资料元数据
        ↓ 内部 HTTP / 服务令牌
FastAPI + LangChain
RAG、联网检索、模型路由、Agent 编排、工具调用
        ↓
云端模型 API / 本地 Ollama
```

- Java 是业务事实来源和权限边界；Python Agent 不直接写核心业务数据库。
- 传统业务数据以 MySQL 为主；向量检索在后续单独接入向量数据库。
- 前端为响应式 Web，优先支持桌面端资料与计划管理、手机端打卡与快速对话。
- 发布路径：Docker Compose 本地启动 → 演示视频 → 公网演示环境。

## 8. 年底前明确不做

- 多 Agent 协作与通用自治规划；
- 原生 App、小程序；
- 社交、共享、协作、教师端、排行榜；
- 在线运行不可信代码的编程判题；
- 自动写入第三方日历；
- 通用桌面控制、任意网页点击、验证码处理。

## 9. 交付标准

年底的可演示版本应至少满足：

1. 用户可注册登录，且数据独立隔离。
2. 用户可导入资料、发起联网检索并看到来源。
3. 用户可通过对话生成计划草案、在结构化表单中调整并确认。
4. 工作台可展示每日任务、进度和站内通知。
5. 用户完成/遗漏任务与测验后，Agent 能在授权范围内调整后续任务，并给出变更记录。
6. Agent 可自动生成有知识点来源的选择题，测验结果会影响后续计划。
7. 用户可查看模型路由、操作审计和计划版本历史。
8. 系统可通过 Docker Compose 启动，有 README、演示数据、测试说明和演示视频。
